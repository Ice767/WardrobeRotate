# Free hosting: Cloudflare Workers + Render + Neon

```
browser ──> Cloudflare Worker (site + /api proxy) ──> Render (Express API) ──> Neon (Postgres)
```

The browser only talks to the Worker's domain. `/api/*` is forwarded by
`frontend/worker.js`, so the auth cookie is first-party and
`SameSite=Lax` keeps working. Nothing here costs money.

## 1. Neon (database)

1. Sign up at neon.tech, create a project (region close to Render's, e.g. Frankfurt or Ohio).
2. Copy the **pooled** connection string. It looks like
   `postgresql://user:pass@ep-xxx-pooler.region.aws.neon.tech/neondb?sslmode=require`.

Tables are created by the backend itself on first start.

## 2. Render (backend)

1. Sign up at render.com with GitHub, then **New > Blueprint** and pick this repo.
   Render reads `render.yaml`.
2. It asks for the values marked `sync: false`:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | the Neon string from step 1 |
| `SEED_ADMIN_PASSWORD` | a long random password, keep it in a password manager |
| `SEED_MANAGER_PASSWORD` | optional: password for the demo carrier `manager@aerofreight.dev` |
| `ALLOWED_ORIGINS` | `https://<name>.<account>.workers.dev` (fill in after step 3) |
| `PROXY_SECRET` | a long random string, e.g. `openssl rand -hex 32`; the same goes into Cloudflare |

`JWT_ACCESS_SECRET` is generated by Render. `TRUST_PROXY=2` is already in the file.

3. After deploy, `https://<service>.onrender.com/api/health` must answer `OK`.
   Any other `/api` path there answers 403: it only accepts requests from the proxy.

## 3. Cloudflare Worker (frontend)

The site is a Worker with static assets: `frontend/wrangler.jsonc` serves the
built React app from `dist/` and runs `frontend/worker.js` only for `/api/*`.

1. dash.cloudflare.com > **Workers & Pages > Create > Import a repository**, pick this repo.
2. Build settings (Settings > Build):
   - Root directory: `frontend`
   - Build command: `npm ci && npm run build`
   - Deploy command: `npx wrangler deploy`
   - Branch: `main`
3. Settings > **Variables and Secrets**:
   - `API_ORIGIN` (Text) = `https://<service>.onrender.com`
   - `PROXY_SECRET` (Secret) = the same value as on Render
4. Build variables: `NODE_VERSION` = `24`.
5. Deploy, then put the `https://<name>.<account>.workers.dev` address into
   `ALLOWED_ORIGINS` on Render.

The Worker name in the dashboard must match `name` in `wrangler.jsonc`.

Check: open the site, search a quote, sign in as `admin@logistics.dev`.

## Secrets: where each one lives

| Secret | Lives in | Never in |
| --- | --- | --- |
| `JWT_ACCESS_SECRET` | Render only | git, Cloudflare |
| `DATABASE_URL` | Render only | git, the frontend |
| `SEED_ADMIN_PASSWORD` | Render + your password manager | git |
| `SEED_MANAGER_PASSWORD` | Render + your password manager | git |
| `PROXY_SECRET` | Render and Cloudflare (same value) | git |

To rotate one: change it in the dashboard, redeploy. Changing `JWT_ACCESS_SECRET`
signs everybody out; changing `PROXY_SECRET` needs both sides changed together.

## Free-tier limits to know

- **Render free sleeps after 15 min without traffic**; the first request then takes
  ~30-60 s. Fine for demos. A paid instance ($7/month) removes it.
- **Neon free** suspends compute when idle (wakes in about a second) and has
  a small storage cap (0.5 GB). Enough for this project for a long time.
- **Rate limits are kept in process memory**: they reset on every restart or sleep.
  Fine with one instance; with several, they need a shared store (e.g. Redis).
- **Schema is created at startup**, no migration tool yet. Needed once an existing
  table has to change.
